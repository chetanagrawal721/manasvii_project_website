Romantic Interactive Website — Step-by-Step Build Playbook

Reference source: Video-33235.mp4  (39s, portrait capture of a phone screen recording of a
Canva-site style interactive romantic web experience — domain shown on-screen:
templatediaryy.my.canva.site )

How to use this document: Build the site in the exact order below. Each Step contains a

Build Instructions block (no code — describes what to construct, how it behaves, and why)

and a ✅ Checkpoint block. Do not move to the next Step until every item in the

Checkpoint passes. This turns the build into a self-verifying pipeline so a developer (or QA

reviewer) can conﬁrm progress objectively at every stage instead of discovering problems

at the end.

Where the reference video does not show something with 100% clarity (e.g., exact hex

codes, exact millisecond timings, exact sound effects), this is explicitly marked "Estimated

Implementation" — build it as reasonably close as possible to what is described, but do not

treat the number as ground truth pulled from the video.

0. High-Level Summary of What You're Building

A single-page, scroll-free, click-through interactive romantic reveal website designed to
be sent as a personal gift/link (a "digital love letter" experience). It is built card-by-card /
scene-by-scene rather than as a long scrolling page — each interaction reveals the next

scene, similar to a slideshow with an unlock gate at the front door.

Full scene order conﬁrmed from the reference video:

1.  Lock Screen — "Enter a passcode" keypad

2.  Wrong Passcode error state (shake/prompt to retry)

3.  Successful unlock transition

4.  "Surprise Awaiting <3" teaser screen

5.  "Click on items to open" — Scene A (gift box + heart-shaped collage of mini icons)

6.  Love letter scene (handwritten-style paragraph over ﬂoral background)

7.  "Everything I Love About You" — heart jar / reasons list scene

8.  "Click on items to open" — Scene B (second heart collage, repeated pattern with a

couple illustration cameo)

9.  Embedded music/video scene — YouTube-style lyric video ("Until I Found You" —

Stephen Sanchez ft. Em Beihold)

10.  Now-playing lyric card with mini audio player controls (loop icon, prev/play/next,

timestamp scrubber)

11.  Photo memory grid scene — "Here's a little reminder of how pretty you are <3" (4-

photo strip with heart icon header)

12.  "Click on items to open" — Scene C (repeats gift/heart collage, leads to ﬁnal reveal)

13.  Final certiﬁcate scene — "BEST GIRLFRIEND AWARD" personalized card with

recipient name and message

14.  (Video ends here; site likely continues/loops or ends on this card — Estimated

Implementation for anything beyond this point)

Design language: Cottagecore / scrapbook / soft pastel romantic aesthetic. Hand-drawn

doodle icons, plaid/gingham backgrounds, serif script headline fonts mixed with a soft

rounded sans-serif body font, pastel pink + sage green + cream color palette, paper/sticker-

collage motifs (washi-tape style borders, "CUTE" signpost sticker, ﬂoating

hearts/stars/butterﬂies).

STEP 0 — Project Setup & Foundations

Build Instructions

Set up a single-page project (static site or single-page app). Because the whole

experience is scene-based, not URL-routed, treat each "scene" as a full-viewport

container that shows/hides rather than a separate page.

Deﬁne a global "scene manager" concept: only one scene is visible at a time; all others

are mounted but hidden (or lazily rendered) so transitions can crossfade instead of
hard-cutting.

Set the base canvas to a ﬁxed content stage that is centered on screen with
letterboxing on very wide screens (the reference video shows the whole experience
living inside a bordered "frame," like a card ﬂoating on a neutral backdrop —
Estimated Implementation: this may just be an artifact of the phone recording rather
than an intentional in-site frame; assume a normal full-bleed responsive layout unless
told otherwise).

Establish font loading, color tokens, spacing tokens, and icon/doodle asset folders
before building any scene (see Design System step below, Step 1).

Decide on tech approach for "clickable items" interactions (Step 5 onward): each item
should be an independently tappable hotspot, not one giant image.

✅ Checkpoint — Step 0

 Project scaffold runs locally / previews in browser with a blank canvas.

 A scene-switching mechanism exists and can toggle between at least 2 dummy

placeholder scenes.

 Base responsive canvas is centered and scales down gracefully at mobile widths (test at

1440px, 768px, 390px).

 Folder structure for assets (fonts, icons, images, audio) exists (see Step 16 for full

structure).

 No console errors on load.

STEP 2 — Build Scene 1: Passcode Lock Screen (First Screen Visitor Sees)

This is the very ﬁrst scene the user lands on. No loading splash was visible in the reference

video before this screen — the site opens directly on the passcode gate. (Estimated
Implementation: a brief branded loading ﬂash may exist before this but was not visibly

captured; if you add one, keep it under 1 second and non-blocking.)

Build Instructions

Layout: Split screen, two vertical halves.

Left half: sage-green gingham/plaid background with pink hearts and stars

scattered as decoration, and a centered oval-framed illustration of the mascot
chick holding a small ﬂower bouquet, itself ringed by a heart-pattern border.

Right half: solid blush-pink background containing the interactive passcode UI.

Right-half content, top to bottom, centered:

1.  Label text: "Enter a passcode" (rounded sans-serif, dark maroon/brown color,

medium weight).

2.  A row of 4 empty square input boxes (rounded corners, white ﬁll, thin border)

representing the 4 digits of the code. Boxes are empty/blank at rest.

3.  Below that, a numeric keypad arranged in the standard phone-dial layout: 1–2–3
/ 4–5–6 / 7–8–9 / *–0–#. Each key is a white circular button with a dark maroon

numeral, sitting on the pink background.

Input behavior:

Tapping a digit key ﬁlls the next empty box left-to-right with a small ﬁlled

marker/icon (in the video, the ﬁlled state shows a small ﬂower/asterisk-style
glyph inside the box rather than the literal digit — use a decorative "ﬁlled" glyph,

not the plaintext digit, for a bit of light security/privacy plus thematic

consistency).

Boxes ﬁll one at a time as each key is tapped; there is no visible backspace key

shown, but you should still implement one for usability (Estimated

Implementation — add a working backspace/clear affordance even though not

explicitly seen).

Once all 4 boxes are ﬁlled, the code is auto-submitted (no explicit "Enter" button

was shown).

Two outcomes after the 4th digit:

Wrong code → go to Step 3 (Wrong Passcode state).

Correct code → go to Step 4 (Unlock transition).

Keep the browser-chrome / URL bar shown in the recording
( templatediaryy.my.canva.site ) in mind only as evidence of the platform used to
prototype this — do not build actual browser chrome into your site.

✅ Checkpoint — Step 2

(stack vertically on narrow mobile if needed — see Step 17).

 Mascot illustration + oval frame + heart border renders on the left panel, decorative

stars/hearts scattered convincingly (not overlapping the illustration or text).

 "Enter a passcode" label displays correctly styled.

 Keypad renders 12 keys in correct telephone-style order (1-9, *, 0, #) with consistent

circular styling.

 Tapping a key visually ﬁlls the next empty box with a marker glyph (not the raw digit).

 After 4 digits entered, system automatically evaluates the code (no manual submit

needed).

 A working (even if visually hidden) backspace/reset exists so a mis-tap doesn't lock the

user out of correcting themselves.

 Correct-code path and wrong-code path are both wired to route to two different next

scenes.
